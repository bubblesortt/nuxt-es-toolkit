# v2.2 Import Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add opt-in deterministic diagnostics that explain every `es-toolkit` import decision without changing default imports or materially regressing v2.1 setup performance.

**Architecture:** The planner gains an optional decision ledger keyed by surface and export name. A pure diagnostics module sorts decisions, derives counters and final imports, and serializes a versioned JSON report. Nuxt writes the report through `addTemplate` only when `diagnostics: true`; the v2.1 benchmark workflow compares v2.1-off, v2.2-off, and v2.2-on scenarios.

**Tech Stack:** TypeScript 5.9, ESM, Nuxt Kit `addTemplate`, Vitest 4, Nuxt test-utils, v2.1 benchmark harness, GitHub Actions, pnpm 10.

## Global Constraints

- Start from the completed v2.1 tip on branch `feature/v2.2-import-diagnostics`.
- Keep `es-toolkit` pinned to exactly `1.50.0` and preserve Nuxt 3.21/Node 20 plus Nuxt 4.5/Node 24 support.
- Add only `diagnostics?: boolean`, default `false`; add no log levels, custom path, presets, DevTools UI, server imports, or type-only imports.
- Disabled diagnostics must register no report template and emit no diagnostics summary.
- Equivalent options must produce byte-identical JSON without timestamps, absolute paths, machine data, or secrets.
- Keep all v2.1 generated-catalogue, runtime-barrel, validation, and normalized-import behaviour.
- Use two-space indentation, LF, single quotes, and no semicolons.
- Do not change `package.json` version, create a tag, publish the package, or push a release.
- Release gates: disabled median setup regression at most 2%; enabled overhead at most 10 ms median and 2 MiB RSS; report/import counters reconcile exactly; bundle growth at most 1%.

```ts
export const toolkitSurfaces = ['base', 'compat', 'fp', 'map', 'set'] as const
export type ToolkitSurface = typeof toolkitSurfaces[number]

export type ImportDecisionStatus = 'registered' | 'excluded' | 'unavailable' | 'overridden'

export type ImportDecisionReason
  = | 'selected-by-mode'
    | 'explicitly-included'
    | 'entrypoint-enabled'
    | 'default-excluded'
    | 'user-excluded'
    | 'not-included'
    | 'surface-disabled'
    | 'entrypoint-disabled'
    | 'compat-preferred'
    | 'method-override'

export interface ImportDecision {
  key: string
  exportName: string
  surface: ToolkitSurface
  status: ImportDecisionStatus
  reason: ImportDecisionReason
  as?: string
  prefixApplied?: boolean
  userAliased?: boolean
}

export const diagnosticsFilename = 'es-toolkit/imports.json'

const surfaceSources: Record<ToolkitSurface, string> = {
  base: 'es-toolkit',
  compat: 'es-toolkit/compat',
  fp: 'es-toolkit/fp',
  map: 'es-toolkit/map',
  set: 'es-toolkit/set',
}

export interface DiagnosticsImport {
  key: string
  exportName: string
  surface: ToolkitSurface
  source: string
  as: string
  reason: ImportDecisionReason
  prefixApplied: boolean
  userAliased: boolean
}

export interface DiagnosticsStatusCounts {
  registered: number
  excluded: number
  unavailable: number
  overridden: number
}

export interface ImportDiagnosticsReport {
  schemaVersion: 1
  moduleVersion: string
  esToolkitVersion: string
  summary: DiagnosticsStatusCounts & {
    candidates: number
    bySurface: Record<ToolkitSurface, DiagnosticsStatusCounts>
  }
  imports: DiagnosticsImport[]
  decisions: Array<ImportDecision & { source: string }>
}
```

Create report object literals with fixed property order: `schemaVersion`, `moduleVersion`, `esToolkitVersion`, `summary`, `imports`, `decisions`.

- [ ] **Step 4: Implement report creation and validation**

Sort a copied decision array by `toolkitSurfaces.indexOf(surface)`, then by `exportName`, then by `key`. Compare strings with `left < right ? -1 : left > right ? 1 : 0`, never locale-sensitive comparison. Reject duplicate `${surface}:${exportName}` identities. Reject a registered decision without `as`, `prefixApplied`, or `userAliased`.

Derive counters from the sorted decisions. Derive `imports` only from registered decisions and add `source: surfaceSources[decision.surface]`. Serialize with `JSON.stringify(report, null, 2) + '\n'`. Format singular `import` for one and plural `imports` for every other count.

```ts
export interface ImportPlan {
  imports: PlannedImport[]
  decisions?: ImportDecision[]
}

const decisionId = (surface: ToolkitSurface, exportName: string) => `${surface}:${exportName}`

export const createImportPlan = (options: PlanImportsOptions): ImportPlan => {
  const decisionMap = options.trace ? new Map<string, ImportDecision>() : undefined
  const record = (decision: ImportDecision) => {
    decisionMap?.set(decisionId(decision.surface, decision.exportName), decision)
  }
```

- [ ] **Step 3: Apply deterministic reason precedence**

Use this precedence when updating active decisions:

1. user exclusion → `excluded/user-excluded`;
2. default exclusion → `excluded/default-excluded`;
3. omitted from an explicit allowlist → `excluded/not-included`;
4. method override → keep `method-override`;
5. compat overlap → keep `compat-preferred`;
6. explicit allowlist registration → `explicitly-included`;
7. enabled entrypoint without an allowlist → `entrypoint-enabled`;
8. ordinary mode registration → `selected-by-mode`.

- [ ] **Step 4: Attach final import naming metadata**
